# Task 08 — Repository Cleanup, CI/OCI and Release Engineering: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the accepted 07J code base into release-candidate-ready software: a restructured repository (`cmd/magnetico` + `internal/app`), a clean lint gate, build information and a legacy-deployment warning, one universal OCI image, native Forgejo release artifacts and a Woodpecker pipeline whose publication depends on verification — **without tagging or publishing anything**.

**Architecture:** (Release path: build once → qualify the digest → promote the digest; see D10–D12.) Behaviour-preserving restructuring first (pure moves, one reviewable commit per move), mechanical lint fixes *before* the moves so they stay small, then two small features (`--version`, legacy warning), then release infrastructure (Dockerfile, GoReleaser, two Woodpecker workflows), then documentation and the report. Every commit builds and passes the narrowest relevant tests.

**Tech Stack:** Go 1.27.4 (`go.mod`: `go 1.26.0`, `toolchain go1.27.4`), golangci-lint 2.15, GoReleaser v2, Docker Buildx, `woodpeckerci/plugin-docker-buildx:6`, PostgreSQL 17, govulncheck, an image scanner (Trivy, version pinned at execution).

**Spec:** the Task 08 text (`/clear` prompt of this session, archived as the "Context" and sections 1–13 reproduced in `docs/wip/08-ci-oci-report.md`), `AGENTS.md`, `docs/engineering-standards.md`, `docs/wip/07J-web-integration-security-report.md`, `docs/wip/rc0-acceptance-checklist.md`.

## Global Constraints

- Branch `refactor/0.8.0-unify-and-new-storage` only; never touch `master`; **do not create tags, push, publish, or change CI secrets**. No production infrastructure; only disposable PostgreSQL.
- Executable name stays `magnetico`. All CLI commands, flags, environment variables, exit codes and runtime behaviour are preserved (the test-harness-only `MAGNETICO_W9_*` variables are the one declared exception, see Decision D3).
- Go **1.27.4 or newer** everywhere (verification, GoReleaser, image build). `govulncheck` is pinned and run with a compatible toolchain.
- Image repositories: `docker.io/skobkin/magnetico-web`, `ghcr.io/skobkin/magnetico-web`; platforms `linux/amd64`, `linux/arm64`; one multi-platform build, each architecture built once.
- `latest` publication entry stays **commented out for every release** (rc and stable) until the owner explicitly enables it. The only tag any publication step may apply is `${CI_COMMIT_TAG}`; an automated invariant test (Task 10) fails the build if an uncommented `latest` or any other alias appears. No `0.8`, `stable`, `edge` aliases.
- Release tag grammar: `^[0-9]+\.[0-9]+\.[0-9]+(-rc\.[0-9]+)?$` (continuing the existing numbering `0.7.1` → `0.8.0-rc.0`; the historical `-rc1` spelling is not accepted for new tags).
- `CGO_ENABLED=0`; non-root runtime user with a fixed UID/GID **10001:10001**; `/data` writable; exec-form entrypoint; no VOLUME declaration (anonymous volumes bit this project before, see `UPGRADE.md`).
- Regular CI must not skip PostgreSQL integration tests silently; full suites run with `-p 3`; no automatic reruns.
- **Merged-state verification of pull requests is preserved.** Redundant push/PR runs are avoided only where merged-state verification is not lost.
- **The published bytes are the qualified bytes.** The OCI image (and the native archives) are built **once**; the container smoke test and the vulnerability scan run on that exact image digest (or `dist/` directory); publication copies that digest/directory. Nothing is rebuilt between qualification and publication.
- **Registry credentials and registry cache writes exist only in trusted workflows**: tag events of `release.yaml`, secrets restricted to `events: [tag]`. `ci.yaml` (which also runs for pull requests) contains no `from_secret`, no registry login, no image push and no cache export.
- **Publication cannot start** unless the verification workflow succeeded **for the same commit**; a failed, skipped or never-run verification blocks it (enforced twice: workflow `depends_on` and an independent guard step, Task 10).
- **Historical reports stay reproducible** after renames: an old→new mapping of every renamed environment variable, test name, build tag and command is documented and checked by a test; persisted benchmark-dataset identifiers are never renamed.
- Never log environment-variable values, DSNs or credentials (legacy warning prints variable **names** only).
- Formatting, restructuring and semantic changes live in separate commits. Historical reports under `docs/wip/` are not rewritten (only additive notes in the index/checklist and the two new Task 08 files).
- Commit trailer: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; author is the configured Git identity (never overridden).
- Do not claim a Woodpecker run, an ARM64 *execution*, or a registry publication happened unless it was verified. Distinguish "configured" from "verified" in every document.

## Review Focus

Failure modes the task implies but no single stage's happy path exercises (each is pinned by a test in the owning task):

1. **Legacy warning must not leak values** — `APP_DATABASE_URL=postgres://u:SECRET@h/db` must never appear in any output; names only (Task 5).
2. **Warning ordering vs. config failure** — `magnetico web` with legacy env *and* no valid config must print the warning *before* the configuration error and keep the same exit code as without the legacy variables (Task 5).
3. **`--help`, `--version`, no-args stay quiet and offline** even with legacy variables set, with no DB/network/config-file access (Tasks 4, 5).
4. **A green pipeline from skipped integration tests** — with `MAGNETICO_TEST_REQUIRE_POSTGRES=1` and an unreachable DSN the suite must *fail* (Task 6).
5. **Diagnostic listener in a release binary** — a default `go build ./cmd/magnetico` and the GoReleaser/Docker builds must not contain the `diag` code; checked by `go version -m` (no `-tags`) and symbol absence (Task 3.6, 8, 9).
6. **Image with a read-only or root-owned `/data`** — start as UID 10001 with a fresh named volume and a bind mount; a crawler must write its queue (Task 8).
7. **Published ≠ qualified image** — the digest in both remote repositories must equal the staged, smoke-tested and scanned digest; no step may rebuild between qualification and publication (Task 10 `verify-published`, workflow invariant test).
8. **Verification skipped or for another commit** — `release.yaml` run where `ci` failed, was filtered out, or reported status for a different SHA must not publish (Task 10 `ciguard` tests with a fake status API: success / failure / pending-then-success / missing / other-SHA / API error).
9. **Untrusted PR code touching secrets or caches** — `ci.yaml` must contain no `from_secret`, `logins`, `cache_images`, `privileged`, DinD or docker socket; PRs never reach `release.yaml` (Task 10 workflow-invariant test).
10. **A historical command that silently breaks after renames** — every `MAGNETICO_W9_*`, `TestW9*`, `w9diag` token and every `go test … -run` target found in `docs/wip/**` must have a mapping entry whose new name exists in the code (Task 3.5 `TestHistoricalNamesAreMapped`).
11. **Renamed persisted dataset identifiers** — a database seeded by the old harness (`w9-large-v1` marker, `w9u*` accounts) must still be recognised by the guards (Task 3.6 `TestGuardsRecognizeLegacySeededDatabases`).
