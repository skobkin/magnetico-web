## S2 material: PHP vectors and password package (steps 5–6)

**Dependencies.** `golang.org/x/crypto v0.59.0` added at first use (approved). It moved `x/sync` v0.24.0→v0.25.0,

**Vectors** (`internal/web/password/testdata/php/`): generated by `php:8.3-cli` pinned to
`sha256:9e2a4e9b1704c05cc469fddbf9b0f0f205e2bb13efd249bbad177289ebdc5c7c` (PHP 8.3.37, Argon2 provider `standard`, libsodium
1.0.18, OpenSSL 3.5.7), `--network none --read-only --cap-drop ALL --user 65534`. 34 cases: argon2i m=16384,t=2,p=4;
argon2id via libsodium (t=4 and t=2, m=64 MiB, p=1); argon2id via `password_hash` (defaults, and t=3,p=2); bcrypt `$2y$` cost 10
(all passwords) and 13 (two). Passwords: ASCII, UTF-8, 1/8/72/73/100/4096 bytes. PHP's own verdicts are stored per case.
README records digest, command and checksums.

**Observed bcrypt behaviour (from PHP itself).** `password_verify` ignores everything beyond byte 72: tail variants verify for
bcrypt at ≥72 bytes and the 72-byte prefix of a longer password verifies; no Argon2 case does. Go matches by truncating to 72
bytes before `bcrypt.CompareHashAndPassword`, which accepts the `$2y$` minor directly (no `$2b$` rewrite needed; the vectors pass).
Passwords containing NUL never match a bcrypt hash (PHP's crypt() sees a C string and could never have hashed one).

**Package** `internal/web/password`: strict PHC parser (argon2i/argon2id, `v=19` only, canonical decimals, parameter order fixed,
m ≤ 65536 KiB, m ≥ 8p, 1≤t≤10, 1≤p≤16, salt 8–64, key 16–64 bytes, unpadded base64), bcrypt `$2y$` only (cost 4–16, exact
60-char form), `Classify` (none/current/legacy/needs-reset), `NeedsRehash`, process-wide `Limiter` (default `max(1,min(GOMAXPROCS,2))`,
3 s wait, `ErrBusy` + `BusyCount`), `Service.Hash/Verify/DummyVerify`, length rules 8–1024 new / 4096 login. Current parameters
m=64 MiB, t=3, p=4 (proposal, unchanged; host benchmark remains a pre-release item).
Deviations from the plan text: none of substance; `NewService` panics on parameters the verifier would reject, and
`DummyVerify` computes its reference hash lazily on first use (that first call costs one extra hash).
